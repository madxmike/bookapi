# Cheat 004 — the 204 carries a JSON body and a content type

**Property.** `book.delete_effective_and_idempotent`: the response to a
successful DELETE is 204 with an empty body and no `Content-Type`.

**Bypass.** The success path reuses `writeJSON` instead of calling
`WriteHeader(http.StatusNoContent)` directly, so it sets
`Content-Type: application/json` and encodes `{"status":"deleted"}`. The status
code, the storage effect, and idempotence are all still correct. A reviewer
could accept it as "consistent with every other response in this handler",
since `writeJSON` is the local convention.

**Must be rejected by.**

- `TestDelete/existing_book_returns_204_with_empty_body` — body and
  `Content-Type` are both non-empty.
- `TestDelete/repeat_delete_returns_204`.
- `TestDelete/request_body_is_ignored`.
- With `BOOKAPI_TEST_DSN` set:
  `TestDeleteIntegrationEffectAndIdempotence` and
  `TestDeleteIntegrationConcurrent` — `requireNoContent` rejects the body.

**Expected verdict.** Rejected.

**Notes.** A 204 with a body is a protocol violation; intermediaries may drop
the body or the connection. The check is cheap, so it lives in both the fake
and the real-store slices.
